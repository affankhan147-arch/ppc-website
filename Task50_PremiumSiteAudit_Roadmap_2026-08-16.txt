ROOT CAUSE OF THE "51-PROSPECT, 0 SENT" MYSTERY - FOUND:
dfw_prospects_initial.csv (the file backing all 3 failed SMTP attempts)
is corrupted. Every one of its 51 rows contains PowerShell Hashtable
reflection properties (IsReadOnly, IsFixedSize, Keys, Values, SyncRoot,
Count) instead of actual names/emails - a scripting bug where a
Hashtable collection was exported to CSV without converting to proper
objects first. There were never 51 real prospects in that file - it's
been empty/garbage since it was generated. That's why 3 separate send
attempts all recorded 0 successes: there was nothing valid to send to.
backlink_prospects.csv (the dashboard-tracking file) is also empty
(header only, 0 rows).
CONCLUSION: no fix needed to the SMTP script itself - the Gmail MCP
send path used above works correctly (just proved it on Principled PM).
The real gap is a genuine prospect list, which never existed. This
directly feeds the "expand prospect list" priority below.
