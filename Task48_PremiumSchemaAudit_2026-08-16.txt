FINDING #1 — FAQ (and HowTo) rich results are DEAD, confirmed via live web
search (not stale training knowledge):
- May 7, 2026: Google stopped displaying FAQ rich results in Search entirely.
- June 2026: Google removes the FAQ filter, rich-result report, and Rich
  Results Test support for FAQ.
- August 2026 (this month): Search Console API support for FAQ ends.
- This is the final step of a 3-year pullback that started restricting FAQ
  rich results in August 2023.
- HowTo rich results were similarly restricted back in August 2023 (mobile
  only, narrow eligibility) -- and this site's howToSchema (used in
  blogEnhancements) is subject to that same restriction.
- Per Search Engine Journal (citing Google's own documentation): keeping
  FAQPage/HowTo schema causes no harm, but produces zero visible SEO
  benefit going forward. No action required either way -- waiting 2 weeks
  to "check if it's rendering" would have been checking a feature Google
  turned off site-wide, not something specific to this site. Good call
  skipping the wait -- there was nothing to observe.
Source: https://www.searchenginejournal.com/google-drops-faq-rich-results-from-search/574429/

FINDING #2 — Organization/LocalBusiness schema is already properly
implemented, and deliberately NOT "upgraded" to a more specific type:
- src/lib/schema.tsx organizationSchema() is live site-wide (injected in
  src/app/layout.tsx on every page) with real telephone, areaServed (every
  city in cities.ts), and openingHoursSpecification 24/7.
- Considered upgrading @type from "Organization" to the more specific
  schema.org "Plumber" type (a LocalBusiness subtype Google recognizes for
  local-service categorization). Decided AGAINST this: src/data/site.ts's
  own legalDisclosure explicitly states "Plumbing Hands is a
  provider-connection website... should not be read as a claim that
  Plumbing Hands maintains a staffed office, address, local license, [or]
  guaranteed availability... in that location." Marking the entity as
  schema.org "Plumber" would contradict that disclosure and risk a
  misleading-markup issue with Google. "Organization" is the correct,
  honest type for a referral/lead-gen platform (same pattern used by sites
  like Angi/Thumbtack) -- left unchanged. This is a case where the "premium"
  move is deliberately NOT changing something, to stay accurate.

A first lighthouse run against https://www.plumbinghands.com/ (the www
subdomain) produced an alarming Performance 54 with LCP 5.9s -- traced this

the canonical apex domain (one hop, by design, matching how the whole site's
canonicals/sitemap/internal links are already built around the apex domain)
-- Googlebot and real visitors never experience this extra hop since nothing
site-wide links to the www version. The bad score was purely a test-URL
artifact, not a real site issue -- verified with curl -IL redirect tracing
before concluding anything, rather than reporting a false regression.
